# Скрипти термінала Hikka

Модуль **Terminal** запускає фонові правила через команду `.ts` (повна назва — `.termscript`). Правила зберігаються в базі даних Hikka, запускаються після перезапуску модуля та виконуються з правами процесу Hikka. Команди нижче введіть від свого акаунта Telegram; якщо префікс команд змінено, замініть крапку.

## Швидкий початок

```text
.ts check on time:every 5min -> run "date" |> notify me
.ts add clock = on time:every 5min -> run "date" |> notify me
.ts list
.ts test clock
.ts status clock
.ts show clock
.ts stop clock
.ts start clock
.ts del clock
```

`.ts check` перевіряє синтаксис і нічого не запускає та не зберігає. `.ts add` зберігає правило й одразу вмикає його; повторне додавання з тією самою назвою замінює попереднє. Назва складається з 1–64 латинських літер, цифр, `_` або `-`. `.ts test` **справді запускає** конвеєр і надсилає повідомлення, якщо в ньому є `notify`. `.ts stop all` і `.ts start all` вимикають та вмикають усі правила. `.ts pause` — синонім `.ts stop`; `.ts rm` і `.ts delete` — синоніми `.ts del`.

## Будова правила

```text
.ts add НАЗВА = ТРИГЕР -> ДІЯ |> НАСТУПНА_ДІЯ
```

Дії виконуються зліва направо: вивід команди передається наступній команді на стандартний ввід або використовується як текст повідомлення. Для розділення дій використовуйте `|>`; старий роздільник ` + ` (з пробілами) також працює. Роздільники всередині лапок не розбивають правило. Звичайна дія — команда оболонки; `run "команда"` також підтримується. Для сповіщення використовуйте `notify me`, `notify telegram CHAT_ID` або `notify tg @username`. Необов'язковий `msg:"свій текст"` замінює вивід попередньої команди:

```text
.ts add heartbeat = schedule every 10min -> run "date -u" |> notify me
.ts add greeting = on time:every 1h -> notify me msg:"Hikka працює"
```

Таймер починає відлік від увімкнення правила. Формати інтервалу: `30s`, `5min`, `2h` (якщо одиницю пропущено, це секунди). Тригер `schedule every` — синонім `on time:every`. Перший запуск відбувається **після** першого інтервалу; для негайного запуску скористайтеся `.ts test НАЗВА`.

## Стеження за файлами

```text
.ts add errors = watch file:/home/hikka/app.log on:change -> cat $file |> notify me
.ts add uploads = watch dir:/home/hikka/uploads on:new-file -> run "basename $file" |> notify telegram -1001234567890
```

`watch file:ШЛЯХ` стежить за одним файлом; `watch dir:ШЛЯХ` — рекурсивно за файлами в директорії. Відносний шлях рахується від поточної директорії термінала (`.pwd`, `.cd`), коли правило додають. Події:

| Подія | Коли виконується |
| --- | --- |
| `on:change` | Файл створено або змінено |
| `on:new-file` | З'явився новий файл |
| `on:delete` | Файл зник |
| `on:any` | Будь-яка з цих подій |

При вмиканні Hikka спочатку робить знімок файлів, тому вже наявні файли не вважаються новими. Частота перевірки задається параметром `SCRIPTS_POLL_INTERVAL` (типово 2 секунди). Список ігнорованих назв/шаблонів — `SCRIPTS_IGNORE_PATTERNS` (типово `.git`, `node_modules`, `venv`, `__pycache__`).

Для кожної події доступні змінні: `$script` — назва правила, `$event` — тип події, `$file` та `$path` — повний шлях до файлу, `$watched` — шлях, за яким стежать. У командах оболонки підставлені значення екрануються як аргументи оболонки; у `notify` вони вставляються як текст. Наприклад:

```text
.ts add arrivals = watch dir:/home/hikka/inbox on:new-file -> notify me msg:"Новий файл: $file"
```

У спостерігачах за файлами дія `cat $file` (також `grep`, `awk`, `sed`, `tail`, `head` із одним аргументом `$file`) читає **лише нову частину файлу** з моменту попереднього спрацювання. Це зручно для логів. Якщо нових даних більше за `SCRIPTS_OUTPUT_BYTES`, передається остання частина з позначкою про обрізання. Якщо потрібен цілий файл, використайте перенаправлення `run "cat < $file"` (вивід так само обмежений налаштуванням). Тестовий запуск завжди читає весь файл. Після перезапуску модуля позиції читання не зберігаються: відлік починається з поточного кінця файлу. Видалений файл уже не можна прочитати через `cat $file`; для `on:delete` скористайтеся `notify` зі змінною `$file`.

Для тесту правила, що стежить за директорією і використовує `$file`, вкажіть конкретний файл:

```text
.ts test uploads /home/hikka/uploads/example.txt
```

## Стан і налаштування

`.ts list` показує збережені правила та їхній стан. `.ts show НАЗВА` показує правило повністю. `.ts status НАЗВА` показує час останнього запуску за UTC та результат; ці діагностичні дані зберігаються в пам'яті й скидаються при перезапуску Hikka. Помилка в одній події записується в стан, але наступні події продовжують оброблятися. Невдалий код завершення команди вважається помилкою та зупиняє поточний конвеєр.

У конфігурації модуля Terminal:

| Параметр | Типове значення | Призначення |
| --- | ---: | --- |
| `SCRIPTS_POLL_INTERVAL` | 2 с | Частота перевірки файлів |
| `SCRIPTS_COMMAND_TIMEOUT` | 60 с | Час на кожну команду оболонки |
| `SCRIPTS_OUTPUT_BYTES` | 32768 | Максимум збереженого виводу кожної команди |
| `SCRIPTS_IGNORE_PATTERNS` | див. вище | Ігноровані шляхи |

Якщо правило не спрацьовує, перевірте `.ts status НАЗВА`, шлях із `.ts show НАЗВА` і доступ Hikka до нього. В Docker шлях указується **всередині контейнера**, а не на комп'ютері хоста. Якщо тест завершується помилкою, текст помилки з'явиться прямо у відповіді. Правила виконують довільні команди з правами Hikka: додавайте лише ті команди й адресати сповіщень, яким довіряєте; не вставляйте паролі в текст правил.
